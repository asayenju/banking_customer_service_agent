# Banking customer service agent

Typed backend around tau2-bench's `banking_knowledge` domain. Goal: a deterministic orchestrator that turns a customer message into intents, decides what to do, and (later) runs banking tools safely.

## Layout
- `backend/` Python 3.12 (`>=3.12,<3.14`), managed with `uv`.
  - `src/banking_tools/`: typed wrapper over 53 tau2 tools. `types.py` (`ToolKind`, `Reversibility`, `ToolSpec`, `AuditEntry`, `ToolResult`), `catalog.py` (the labelled table, `get_registry()`, `EXCLUDED`, `render_markdown()`), `args.py` (pydantic arg models built from tau2 signatures), `session.py` (`BankingSession`).
  - `src/orchestrator/`: the central agent's decision layer, spec in `docs/prd-orchestrator-routing.md`. `types.py` (`IntentKind` 22 kinds, `Intent`, `Decomposition`, `Decision`), `taxonomy.py` (tool to kind, checked against the catalog), `bands.py` (0.85/0.65, plus `WRITE_KIND_ASK_AT` 0.95: a write also needs Jev's kind answer alone at 0.95 or it asks), `scoring.py` (`Scorer` Protocol, per-intent confidence), `auth.py` (2-of-4 verified-caller gate), `decision.py` (run/ask/escalate, explicit yes bound to a fingerprint), `unclear.py` (greeting pre-check, help menu), `routes.py`, `plan.py` (waves), `executor.py`, `mocks.py` (`ScriptedRoute`), `reply.py`, `decomposer.py` (`Interpretation`, `Decomposer` Protocol), `orchestrator.py` (`Orchestrator.handle_turn`), `trace.py`. Real parts: `config.py` (loads repo-root `.env`), `llm.py` (`LLMClient`, `LiteLLMClient`, `FakeLLMClient`), `sanitize.py` (`redact`), `validate.py` (pure post-checks), `llm_decomposer.py` (`LLMDecomposer`), `policy.py` (`ACTION_POLICY`, shared by the decomposer prompt and the eval labeler), `grounding.py` (drops an unasked `REQUEST_HUMAN`), `request_type.py` (`CommunicationType`; a write survives only as an action request, otherwise it is dropped or becomes a read), `evidence.py` (drops intents whose quoted evidence is not in the message, or lacks a trigger word (a quote with one word changed still counts) for `REQUEST_HUMAN`, `UPDATE_PROFILE`, `REPORT_FRAUD_OR_LOSS`; never drops the last intent), `evaluation/` (opt-in live eval, see below), `jev.py` (`JevScorer`, `make_jev_scorer`). Tests in `tests/orchestrator/`; whole-conversation scenarios in `test_scenarios.py` using `scenario_kit.py`; schema snapshot in `tests/orchestrator/snapshots/`.
  - `src/main.py`: FastAPI hello-world stub. `src/models/` is empty.
  - `tests/`: `test_types.py`, `test_catalog.py`, `test_args.py` (snapshot in `tests/snapshots/arg_schemas.json`), `test_session.py`.
- `tau2-bench/`: git submodule (fork `asayenju/tau2-bench`), installed as an editable path dependency. Never edit it. Domain code: `tau2-bench/src/tau2/domains/banking_knowledge/`; data: `tau2-bench/data/tau2/domains/banking_knowledge/` (`tasks.json` has 97 tasks with free-text user instructions and expected tool actions).
- `docs/`: PRDs (`prd-banking-tool-wrapper.md` is the format precedent: Why, What, How, Constraints and risks, Issues and acceptance criteria, Decisions). `docs/banking-tool-catalog.md` is generated by `render_markdown()`; do not hand-edit.

## Commands (run in `backend/`)
- `uv sync --extra jev` (a plain `uv sync` uninstalls the optional `typesafe-sdk` that the live Jev scorer needs)
- `uv run pytest` (offline, no API keys needed)
- `uv run mypy --strict src/banking_tools src/orchestrator`
- Refresh the args snapshot: `UPDATE_SNAPSHOTS=1 uv run pytest tests/test_args.py`
- Refresh the orchestrator schema snapshot: `UPDATE_SNAPSHOTS=1 uv run pytest tests/orchestrator/test_intent_types.py`
- `tau2 tasks subset` needs `rank_bm25`, which is not installed; read `tasks.json` directly to sample tasks.
- macOS hidden `.pth` fix if `tau2` imports fail outside pytest: `chflags -R nohidden backend/.venv`. iCloud (`~/Documents`) re-hides the venv's editable `.pth` file and Python 3.12 skips hidden ones. pytest no longer depends on it (`pythonpath` includes `../tau2-bench/src`).

## Conventions
- Models are pydantic, frozen and strict (`extra="forbid"`, `strict=True`, `frozen=True`); enums are `StrEnum`; full type annotations, mypy strict.
- Failures are values, not exceptions (`ToolResult.ok=False`).
- One `BankingSession` per scenario, each with a deep copy of the pristine DB; sessions never share state. Audit log redacts `pin`, `new_pin`, `current_pin`, `cvv`.
- Tool labels: read / write (reversible or irreversible) / handoff. The catalog is the source of truth, not tau2's decorators.
- Tests are pytest, offline, hard-coded ids (e.g. `CARD = "dbc_lj82d4f1a9_bluest"`), no shared fixtures for DB isolation.
- Orchestrator tests are scripted end to end (decomposer, scorer, directory, routes) and assert on the `Trace`. Every row of the PRD edge-case table needs a `@covers(...)` scenario in `test_scenarios.py`; a test reads the table and fails if one is missing.
- Safety rules to keep: irreversible actions never run without the customer's yes to the exact details; the list of kinds that skip a yes (`decision.NO_YES_NEEDED`) and the read-only list (`plan.READ_ONLY_KINDS`) are explicit so new kinds fail closed; error messages from routes and scorers are recorded by exception type only, never text.
- Commits: one sentence, no prefix, issue in the sentence ("Close Issue #4 as ..."). Single linear branch `main`.
- Issues are created from the PRD with `gh issue create`; acceptance criteria are repeated in the PRD.

## LLM / Jev
- `litellm` is a direct dependency pinned `>=1.80.15,<1.82.7` (inside tau2's range); keep any change inside it. `typesafe-sdk` is the optional extra `jev` (`uv sync --extra jev`).
- Keys live in the git-ignored repo-root `.env`: `OPENAI_KEY` (passed to LiteLLM as `api_key`), `JEV_KEY`, optional `DECOMPOSER_MODEL` (default `openai/gpt-4o-mini`). `.env.example` lists the names. Tests never need them; live tests are opt-in (`RUN_LIVE=1`).
- The decomposer sends only redacted text, uses OpenAI strict JSON schema (no free-form objects: slots and claims are name/value lists), and never raises. Models other than OpenAI would need the schema checked.
- Jev (TypeSafe AI) is a hosted non-LLM decision model: `client.system_one(state=..., questions={...: {"type": "noul", ...}})` returns yes/no probabilities, no text. Pinned to `jev-1.13.0` (works though the account's model list shows only `jev-latest`/`jev-preview`; `jev-latest` already moves to 1.14.0). It is weak on numbers, dates and adversarial text, so slot completeness is computed in code, injection-flagged messages are not sent, and its confidence never authorizes an irreversible action.

## Evaluation (opt-in, live, needs keys)
Run from `backend/` with `PYTHONPATH=src:../tau2-bench/src` if `orchestrator` is not importable (hidden `.pth`):
- `uv run python -m orchestrator.evaluation run --trials 5 --set evals/<set>.json` scores the decomposer: a trial passes when the action kinds found equal the kinds the message states (read-only kinds and OTHER ignored). Reports pass@k, pass^k, trials that dropped a request vs added an action, and per-kind precision/recall.
- `... jev --sets <paths>` checks how well Jev's kind answer separates right from wrong intents.
- `... e2e --sets <paths>` runs one turn per message through the whole `Orchestrator` (real decomposer and Jev, verified caller, mock routes) and counts writes by what the customer asked for and what the decision layer did. `IRREVERSIBLE RAN WITHOUT A YES` must be 0, and `of a kind that skips the yes` is the tripwire for `FREEZE_CARD`/`UNFREEZE_CARD`/`UPDATE_PROFILE` (decision in the routing PRD). It found that missing details escalated instead of asking.
- Sets: `banking_eval_set.json` (50, used to tune the prompt), `banking_holdout_set.json` (22, partly looked at while tuning, so no longer independent), `banking_minimal_pairs.json` (35, hand-written, known labels, no labeler: negation, hypotheticals, question vs request; written after the prompt, so easy), `banking_holdout2_set.json` (25, built with `build --no-action-tasks`, mostly customers who should trigger nothing; every tau2 task with a write action is already in the first two sets).
- Labels were written by a labeler model and are noisy at the edges. Known: 092 was relabelled `[]` by hand; 028 (`REQUEST_HUMAN` from "need someone to investigate") is borderline; 099 and 100 are near-identical messages with opposite labels; "I'm looking for a credit card" is labelled `[]` while the prompt treats "I want to open X, which one?" as `OPEN_ACCOUNT`. Decide that rule before trusting holdout2's score.
- Reports include false write rate on no-action messages and write precision/recall. Latest (3 trials): minimal pairs 1.00, main 0.92, holdout 0.97, holdout2 0.83. Older 5-trial results (temperature 0 still varies a little between runs, so a 1 to 2 point change is noise): main pass@1 0.90, holdout 0.96, holdout2 0.82 (pass^5 0.76). The recurring failure is an extra action from a symptom or a question (`FEE_OR_INTEREST_ADJUSTMENT`, `OPEN_ACCOUNT`, `CARD_CONTROLS`), not a dropped request.

## Specialist agents (`backend/src/agent/`, `knowledge/`)
PRD: `docs/prd-specialist-agents.md`. Offline tier-1 evidence is `agent/tier1.py` (gold replayed through the real specialist, compared with tau2's database). Live runs are expensive and go only through `uv run python -m agent.live --tasks <ids or specialist>`: no "all", at most 5 tasks by default, a printed estimate that needs `--yes`, a dollar cap enforced on real usage, and cassettes in `backend/evals/cassettes/` (git-ignored) so a task is paid for once. The default `pytest` blocks `litellm.acompletion` (`tests/conftest.py`); live tests need `RUN_LIVE=1`.

### Credit-card specialist (`agent/specialists/credit.py`, `credit_rules.py`, `agent/workflows/credit_*.py`)
PRD: `docs/prd-credit-card-specialist.md`; every policy decision with its evidence: `docs/credit-policy-decisions.md`. Tier is by card type (`workflows/credit_tiers.py`); the bank's credit tools check almost nothing, so `credit_rules.py` holds a validator per write tool plus read-backs; four workflows (closure with retention asked as pending questions, limit increase, dispute, replacement) where the model reports what the customer said and code decides. `agent/handoff.py` writes the note for a person from the audit. A credit limit request is planned before a dispute or replacement (`orchestrator/plan.py`). Offline evidence: `uv run python -m agent.credit_report` (18 tasks: 17 pass, task 048 departs for a documented reason in `evals/policy_departures.json`).

### Accounts and money-movement specialist (`agent/specialists/accounts.py`, `accounts_rules.py`, `agent/bank_accounts.py`, `agent/workflows/account_*.py`)
PRD: `docs/prd-accounts-money-specialist.md` (its last section lists what changed while building); every policy decision with its evidence: `docs/accounts-policy-decisions.md`, whose statements about the bank's tools are tests in `tests/agent/test_accounts_policy.py`. Handles OPEN_ACCOUNT, CLOSE_ACCOUNT, TRANSFER_FUNDS and PAY_CREDIT_CARD. The bank's account tools check little (no same-owner check on transfers, any class string opens, the early-closure fee is checked but never debited, a duplicate open is a silent no-op), so `accounts_rules.py` has a validator per write tool plus read-backs. `bank_accounts.py` reads both of the bank's record layouts (a tool-opened account has `account_type`/`account_class`, the rest `class`/`level`) and resolves an account only among the customer's own. Class names, caps, closing tiers, pages, promotions and APY pairings are data in `workflows/account_products.py`; `workflows/account_catalogue.py` offers only classes the open validator would accept, with promotions by date. Four workflows (open, close funds-first, transfer, pay card); workflow steps carry a `note` so the plan names accounts, not ids. The fee-sized balance in an account inside its window is never moved and the fee is never waived. An opening is planned before a closing in the same turn, and a closing is skipped if its opening did not complete (`plan.py`, `closes_wait_for_openings`). Wires, ACH, bill pay and sending money to someone else are a hand-off; a check deposit gets the customer's own steps. Offline evidence: `uv run python -m agent.accounts_report` (19 tasks, all pass strictly, no departures).
